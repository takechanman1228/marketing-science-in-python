3.2 A/B 测试设计

关于中文版
本页是英文版 Marketing Science in Python 的AI翻译。英文版为正式版本，如有出入，以英文版为准。代码、Notebook 和图片中的文字保持英文。 阅读英文版

你的团队刚刚在新的结账页面上完成了一次为期两周的 A/B 测试。每个人都迫不及待想看结果。然后数字出来了：

版本 用户数 转化数 转化率
对照组 5,000 115 2.30%
实验组 5,000 127 2.54%

实验组看起来稍好一些，提升了 0.24 个百分点。但双比例 z 检验给出的 p 值是 0.43：

import numpy as np
from statsmodels.stats.proportion import proportions_ztest

conversions = np.array([127, 115])   # treatment, control
users = np.array([5000, 5000])
stat, p_value = proportions_ztest(conversions, users, alternative="two-sided")
print(f"p-value: {p_value:.2f}")     # 0.43

于是团队说：“不显著。改版没用。我们接着做别的吧。”这个结论并没有数据支持。p 值为 0.43 并不意味着没有效应。它意味着这次测试无法把一个小效应与随机噪声区分开。实验组的版本可能真的更好，只是数据说不清。“没有效应”和“我们无法判断”之间的差别，取决于测试是否有足够的功效。

统计功效

统计功效是指，如果某个特定大小的效应真实存在，你的测试能够检测到它的概率。大多数团队以 80% 的功效为目标，这仍然留下 20% 的概率错过一个那么大的效应。

想象把同一个 A/B 测试重复许多次。如果改版没有真实效应，估计的提升会在零附近上下波动。如果改版真的改善了转化，估计的提升会在真实提升附近上下波动。功效就是测试结果离零足够远、让我们能够检测到该效应的概率。

对于购买这样的低转化事件（比如 2% 的转化率），检测 0.5 个百分点的提升需要每组好几千名用户，而大多数团队的样本远少于此。这是大多数团队低估的部分：检测小幅提升通常需要的流量远超直觉。

计算样本量

那么你到底需要多少用户？确定测试规模需要四个输入：基线转化率、值得检测的最小提升（即最小可检测效应，MDE）、你愿意容忍的假阳性率（\(\alpha\)，通常为 0.05），以及你想要的功效（\(1 - \beta\)，通常为 0.80）。

关键直觉是：

\[n \propto \frac{1}{\text{MDE}^2}\]

如果你想检测的提升减半，你需要的用户数大约是原来的四倍。用 Python 实现：

from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

baseline_cvr = 0.02
target_cvr = 0.025
effect_size = abs(proportion_effectsize(target_cvr, baseline_cvr))

analysis = NormalIndPower()
required_n = analysis.solve_power(
    effect_size=effect_size,
    alpha=0.05,
    power=0.80,
    ratio=1,
    alternative="two-sided",
)
print(f"Required sample size per group: {required_n:.0f}")  # ~13,800

要检测从 2% 基线到 2.5% 的提升，每组需要大约 13,800 名用户。实践中，团队会向上取整，并为追踪丢失和被排除的用户留出余量，因此他们会按大约 15,000 来规划。

这条曲线让主要教训一目了然：样本量并不是线性增长的，而是随着目标提升的缩小而陡峭攀升。这就是为什么在低转化指标上测量小幅改进代价高昂。

上线前先做决定

在启动测试之前，写下四项决定：

  1. 主要指标：由哪个指标来判定测试结果？
  2. MDE：多大的提升才足够重要？
  3. 样本量与时长：在评判结果之前你要收集多少数据？
  4. 护栏指标：哪些东西不能变差（每用户收入、页面加载时间、客服工单）？

提前写下这些，可以防范两种悄悄推高假阳性的习惯：偷看（测试一看起来显著就停止）和指标钓鱼（在众多指标中挑出恰好有变动的那个来汇报）。

CUPED：从同样的样本中获得更高精度

当所需样本量遥不可及时，你并不总能增加更多用户、门店或市场。CUPED（Controlled-experiment Using Pre-Experiment Data 的缩写）有时可以利用实验之前的信息，从同样的数据中获得更高的精度。微软的实验团队在 2013 年提出了这一方法，目的是在不收集更多数据的情况下让在线实验更加灵敏 (Deng 等 2013年)，此后它已成为大规模实验中标准的方差缩减工具。

思路很简单。如果一位客户在实验之前就已经是高消费者，那么无论是否接受处理，他在实验期间很可能也会继续消费。CUPED 从结果中减去这部分可预测的成分，使比较聚焦于测试期间真正发生变化的部分。

在图中，客户 A 在活动前消费了 $100，活动期间消费了 $110。根据这一历史，你会预期大约 $102，所以高出预期的提升只有 $8，而不是全部的 $110。剔除每位客户可预测的消费，可以在不改变平均处理效应的情况下收窄结果的离散程度，从而让效应更容易被检测到。

同样的思路也适用于门店层面或市场层面的实验。假设一家零售商想测试一项店内促销。把数百家门店随机分成实验组和对照组在操作上可能不现实，而且每家门店都不一样：有的更大，有的客群不同，有的受到当地事件的冲击。CUPED 可以利用每家门店实验前的销售额，去除这种可预测的门店间差异的一部分。它不会创造更多门店，也不会修复薄弱的设计，但当实验前销售额能够很好地预测测试期间的销售额时，它可以让规模较小的门店测试更加精确。

形式上，设 \(Y\) 为结果，\(X\) 为实验前的协变量（例如此前 30 天的购买）。调整后的结果为：

\[Y_{\text{CUPED}} = Y - \theta \cdot (X - \bar{X})\]

其中 \(\theta = \text{Cov}(Y, X) / \text{Var}(X)\)。调整后结果的方差降为 \(\text{Var}(Y_{\text{CUPED}}) = \text{Var}(Y)(1 - \rho^2)\)，其中 \(\rho\) 是 \(X\) 与 \(Y\) 之间的皮尔逊相关系数。如果 \(\rho = 0.7\)，CUPED 大约能去除一半的方差，相当于样本量翻倍所能带来的精度。Netflix 后来发表的案例研究报告了其大规模在线实验中类似的方差缩减 (Xie 和 Aurisset 2016年)。最常用的协变量是同一指标在实验前时期的测量值，它通常给出最强的相关性。

在代码中，这一调整只需几行。在一个模拟的营销活动中，实验前消费与实验期间消费的相关系数约为 0.75，它把提升的标准误削减了约三分之一：

import numpy as np

# df: one row per customer — pre_spend (prior 30 days), campaign_spend, treatment (0/1)
theta = np.cov(df["campaign_spend"], df["pre_spend"])[0, 1] / df["pre_spend"].var()
df["cuped_spend"] = df["campaign_spend"] - theta * (
    df["pre_spend"] - df["pre_spend"].mean()
)

for metric in ["campaign_spend", "cuped_spend"]:
    t = df.loc[df["treatment"] == 1, metric]
    c = df.loc[df["treatment"] == 0, metric]
    se = np.sqrt(t.var() / len(t) + c.var() / len(c))
    print(f"{metric:15s} lift={t.mean() - c.mean():.2f}  SE={se:.3f}")
# campaign_spend  lift=0.97  SE=0.549
# cuped_spend     lift=1.07  SE=0.364   (33.7% smaller SE — like a much bigger sample)

点估计略有移动（0.97 → 1.07）：CUPED 去除了原始差距中由两组之间实验前偶然不平衡造成的部分，因此它瞄准的仍然是同一个真实效应，同时区间收窄了。配套 Notebook 端到端地模拟了 df（并报告 p 值，这里从 0.08 降到 0.003），你可以改变相关系数，观察精度增益如何缩小或扩大。

当测试无法下结论时

回到结账页面的测试。正确的问题不是“p 值是否低于 0.05？”，而是“测试是否足够精确，足以排除一个我们会在意的效应？”

看看置信区间。观察到的提升是 +0.24 个百分点，但 95% 区间从 −0.36 到 +0.84 个百分点，宽到既包含小幅损失也包含可观的收益。这次测试无法下结论：它没有证明改版有效，但也肯定没有证明它无效。只有当区间足够窄、并且排除了任何值得上线的提升时，你才能合理地把一个处理放到一边。

换句话说，不显著的结果并不自动等于失败的处理。它可能只是意味着测试太小、噪声太大，或者在一个不寻常的时期内运行。

要点

  • 针对值得检测的效应来设计：在上线前确定主要指标、MDE、样本量和护栏指标。样本量与 \(1/\text{MDE}^2\) 成比例，所以提升减半，用户数就要变成四倍。
  • 不显著的结果不是没有效应的证据。用置信区间来评判：如果值得上线的提升仍然落在区间之内，测试就还没有给出答案。
  • 当你无法购买更多流量时，CUPED 可以转而购买精度，用实验前的协变量从比较中剔除方差。
