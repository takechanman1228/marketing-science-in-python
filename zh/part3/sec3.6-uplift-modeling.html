3.6 用于定向投放的增益建模

关于中文版

下一次营销活动应该发给哪些客户？大多数团队用响应模型来回答：按购买可能性给客户排序，然后定向投放给名单的顶端。问题在于，许多高概率客户无论你是否触达都会转化，所以把钱花在他们身上不会改变结果。增益建模（uplift modeling）转而按“触达预计会在多大程度上改变客户行为”来排序：它瞄准的是那些因为你触达了才购买的人，而不是那些本来就会买的人。这正是它在触达有成本时的价值所在：预算应该投向能改变结果的地方，而不是搭上一笔本来就要发生的销售的顺风车。

  • 响应模型预测的是：\(P(\text{purchase})\)
  • 增益模型预测的是：\(P(\text{purchase} \mid \text{treated}) - P(\text{purchase} \mid \text{not treated})\)

第二个量就是每位客户的处理效应，即 CATE；§3.5 讲过如何估计它。这个得分只是测量步骤。下一步是把它变成一套定向策略，并在保留数据上检验按这个排序行动是否真的能带来价值。

理解要定向投放的客户

要用好增益建模，不妨在脑中勾勒四类客户，按他们对触达的反应来定义。

  • 可说服者（Persuadables）：只有被触达才会购买。他们是理想的目标；邮件改变了他们的行为，你的全部回报都来自他们。
  • 必然购买者（Sure Things）：无论如何都会买。触达他们只是花掉预算，却没有任何增量销售。
  • 无望者（Lost Causes）：从不购买。触达是浪费。
  • 勿扰者（Sleeping Dogs）：本来会自己购买，但触达反而把他们推开。触达他们实实在在地让你蒙受损失。

追逐购买可能性的响应模型，会把名单填满必然购买者。追逐处理效应的增益模型，则瞄准可说服者并避开其余各类。这个差别就是全部要点。

增益建模有两个方法家族：§3.5 的元学习器，以及直接以增益为分裂依据构建的决策树，后者的优势是可以同时处理多个处理组（在一个模型里比较 5%、10% 和 20% 的优惠）。本章沿用元学习器的路线，像 §3.5 一样使用 EconML，再加上 scikit-uplift 来评估排序；Uber 的库 CausalML 则是树类方法的公认大本营。

数据集

我们重用 §3.5 的半合成 MineThatData 示例：Kevin Hillstrom 的随机化邮件实验，限定为男装邮件和不发邮件两个组（42,613 名客户，大致按 50/50 划分）。客户特征和处理分配是真实的；只有结果是模拟的，所以我们知道每位客户的真实效应，可以在每一步给模型打分。我们植入的平均效应约为 11 个百分点，对男装购买者、近期活跃客户和多渠道购物者更大。

from msbook.data import load_minethatdata

df = load_minethatdata()
df = df[df['segment'].isin(['Mens E-Mail', 'No E-Mail'])].copy()
df['treatment'] = (df['segment'] == 'Mens E-Mail').astype(int)

每一行是一位客户：真实的 Hillstrom 特征、随机化的处理标记，以及我们用来打分的模拟转化结果。

训练增益模型

增益得分就是 CATE。我们重新拟合 §3.5 的元学习器，保留在保留集上对真实效应还原得最好的那一个：S-Learner，它的估计与真值的相关性为 0.77（完整比较见 §3.5 的 表 1）。它预测的 CATE 就是增益得分，拟合用的是与 §3.5 相同的 EconML 调用，所以没有任何新东西需要安装：

from econml.metalearners import SLearner
from lightgbm import LGBMRegressor

uplift = SLearner(overall_model=LGBMRegressor())
uplift.fit(Y=conversion_train, T=treatment_train, X=X_train)
uplift_score = uplift.effect(X_eval)   # one CATE / uplift score per customer

评估

只有当得分较高的客户确实比得分较低的客户产生更多增量转化时，增益得分才有用。第一项检查是局部的：把保留的客户按增益得分分成十分位（十分位 0 = 得分最高），读取每个十分位内的增益。半合成的设定让我们可以比较三列：模型预测的增益、在随机化保留集上观测到的增益（每个十分位内实验组与对照组转化率之差），以及真实增益。

最高、中间和最低十分位的预测、观测与真实增益。
十分位 预测增益 观测增益 真实增益
0（得分最高） 22.7% 16.8% 18.0%
4（中间） 11.4% 10.8% 13.4%
9（得分最低） 1.2% 3.3% 5.1%

具体各行有噪声，观测增益一列尤其如此，因为每个十分位只有大约 1,300 名客户。但排序是有效的：顶部十分位的观测增益和真实增益（约 17 个百分点，而平均值是 11 个百分点）远高于底部十分位。我们需要的正是这个顺序。我们不需要每个十分位都完美单调；关注排序的顶端，而不是尾部的单独几行。

十分位表是局部视角。全局诊断是 Qini 曲线：把客户从最高增益到最低增益排序，然后画出随着你在名单中定向得越来越深、经处理组规模归一化后的累计增量转化。一个包含真实信号的排序，其曲线会高于随机触达客户时你会看到的那条对角线。（普通的增益曲线在未归一化的尺度上呈现同样的形状；Qini 曲线是比较增益模型的标准，因为当受处理比例沿排序变化时它依然可靠。）

这里的曲线从一开始就远高于随机线：定向投放给排序前 30% 的客户，可以捕获约 42% 的增量转化（随机定向则是 30%），前一半则捕获约 62%。这就是这个排序值得据以行动的原因。

两个汇总面积都是正的，形式上意味着该排序优于随机定向：

from sklift.metrics import uplift_auc_score, qini_auc_score

auuc = uplift_auc_score(conversion_eval, uplift_score, treatment_eval)
qini = qini_auc_score(conversion_eval, uplift_score, treatment_eval)
print(f"AUUC = {auuc:.4f}   Qini = {qini:.4f}")   # both > 0 ⇒ better than random
AUUC = 0.0404   Qini = 0.0695

它们把整条曲线压缩成一个数字。比较增益模型时该引用的是 Qini 系数：当排序胜过随机时它为正，并且在同一个保留集上可跨模型比较，尽管它不是一个绝对的业务指标。AUUC 在增益曲线上度量同样的思想。两者都有一个注意事项：S-Learner 是在这同一个保留集上选出来的，所以这些数字偏乐观。正式的生产报告会保留一个未被动过的最终保留集，用于给出标题数字。

提取目标客户名单

只有把得分与业务指标联系起来，它才能付诸行动。假设每一次增量转化值 $30 的利润，触达一位客户的成本是 $3。那么你只应处理增益超过 10% 盈亏平衡点的客户，而每位客户的预期净价值就是其增益乘以转化价值，再减去触达成本：

value_per_conversion = 30.0   # $ margin per incremental conversion
treatment_cost = 3.0          # $ per contacted customer (email + offer)

net_value = uplift_score * value_per_conversion - treatment_cost
# Target the deciles (or customers) where net value > 0.
盈亏平衡切点附近各十分位的每客户预期净价值。
十分位 预测增益 每位客户的净价值 决策
3 13.0% $0.90 投放
4 11.4% $0.41 投放
5 9.7% -$0.10 跳过
6 7.6% -$0.71 跳过

在每次增量转化 $30 利润和 $3 触达成本的条件下，盈亏平衡增益是 10%。前五个十分位的预测增益越过了这个阈值，所以策略是定向投放名单的前一半，跳过其余部分。具体常数只是为了演示；重要的是规则：把增益换算成预期价值，减去触达成本，只在结果为正的地方投放。这就成了你的客户名单。在这次运行中，预测列和观测列并不完全一致：观测净价值在预测切点之后的两个十分位里仍然为正。这个边界地带，正是在你投入预算之前，一个新的随机化保留集最能证明自身价值的地方。

要点

  • 增益按触达能在多大程度上改变客户行为来排序，而不是按购买可能性。这就是让预算避开必然购买者、远离勿扰者的关键。
  • 先在一个新的随机化保留集上确认排序胜过随机，再把增益换算成预期净价值：只在增益乘以转化价值超过触达成本的地方投放。
