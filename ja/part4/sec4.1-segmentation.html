4.1 顧客セグメンテーション

日本語版について
このページは英語版 Marketing Science in Python のAI翻訳です。英語版を正本とし、差異がある場合は英語版を優先してください。コード、Notebook、画像内の文字は英語のままです。 英語版を読む

セグメンテーションのプロジェクトでは、プレゼンテーションだけでなく、チームが実際に使えるものを作る必要があります。本当の成果物は、CRMや広告プラットフォームへ直接つながる segment_id と、各セグメントについて、その人たちは誰か、なぜ重要か、チームはどのような行動を取るべきかを示す簡潔な概要です。

この章では、そのような成果物を3つの手順で作ります。

  1. 最初に、現在価値で顧客を順位づけします。デシル分析とRFM（Recency、Frequency、Monetary）によって、価値に基づくセグメントをすばやく作れます。
  2. 次に、行動で顧客をグループ化します。行動クラスタリングは、価値階層だけでは捉えられないパターンを明らかにします。
  3. 最後に、購入の意味を加えます。埋め込みベースのセグメンテーションは、顧客がいくら使うかだけでなく、実際に何を購入しているかを示します。

行動変数とプロフィール変数

顧客セグメントを作る際、変数は大きく2種類に分かれます。行動変数は、最終購入からの期間、頻度、支出、購入カテゴリー、商品の幅、返品、値引きへの依存など、顧客が何をするかを表します。プロフィール変数は、年齢、所得、世帯構成、地域、ロイヤルティ階層、チャネル嗜好など、顧客が誰であるか、どこで接触できるかを表します。

マーケティングのセグメンテーションでは、行動変数の方が強い基盤になります。誰かが見たもの、購入したもの、類似顧客が選んだものは、通常、人口統計より次の行動をうまく予測します。「この商品は30代男性向け」「このオファーは高所得者向け」のように人口統計だけへ頼ることは、顧客の実際の購入履歴よりはるかに弱いシグナルです。

プロフィール変数にも役割があります。セグメントを作った後に、各群に誰がいるか、どこで接触できるか、コミュニケーションをどう調整するかを理解するために使います。

単純な方法から始める：デシルとRFM

最も単純なのはルールベースの方法です。アルゴリズムへ頼らず、自分で閾値を定義します。デシル分析とRFMが最も一般的な例です。

デシル分析

デシル分析は、売上に基づいて顧客を同じ人数の10群へ分けます。多くの場合、パレートの法則に従い、少数の群が売上の大半を生みます。最上位デシルには維持施策とVIP対応を行います。次の3デシルは成長キャンペーンの主な対象です。中央の3デシルには低コストの自動ナーチャリングを行い、下位3デシルは高価なオファーから除外します。すばやく設定でき、チームへ明確な行動計画を渡せます。

RFM分析

RFMは、より細かな見方を提供します。休眠した高額購入者、新しく頻繁に購入する顧客など、チームがすでに使っている考え方に合うため、ダイレクトマーケティングで最も広く使われるセグメンテーションの枠組みです。

独立ソートでは各変数を別々に五分位へ分け、3桁のスコア（R=5、F=4、M=3）と最大125群を作ります。逐次ソートでは分割を入れ子にします。最初にRecency、次に各Recency群内でFrequency、最後にMonetaryで分けるため、Recencyへ最も大きな重みが置かれます。

ヒント1回の呼び出しでRFMスコアリング

Section 4.2のCLVモデリングで使うPyMC-Marketingには、四分位に基づく rfm_segments() ユーティリティがあります。取引表からR、F、Mをスコアリングし、名前付きセグメントを直接割り当てます。K-Meansより柔軟性は低いものの、実務ではうまく機能し、非常に大きな顧客基盤でも高速です。

デシルとRFMはすばやく設定でき、簡単に使えます。しかし、作れるのは価値階層だけであり、完全な顧客プロフィールではありません。似たRFMスコアを持つ2人の顧客も、大きく異なる行動を取る可能性があります。一人は多くのカテゴリーで定価商品を購入し、もう一人は単一カテゴリーの値引き商品だけを購入するかもしれません。こうした違いを見るには、価値階層から、より豊かな行動変数へ移る必要があります。

K-Meansによる行動クラスタリング

K-Meansは古典的なクラスタリングアルゴリズムですが、今でもマーケティングのセグメンテーションにうまく機能します。支出が支配的にならないよう、StandardScalerで特徴量を正規化し、6〜10個の行動変数から始めます。RFMに加え、平均注文金額、バスケットサイズ、返品率などが有用です。

スケーリング前に、歪んだ変数を対数変換します。支出、頻度、最終購入からの期間、バスケットサイズは通常、強く右に歪みます。少数の顧客が、ほかの全員よりはるかに多く購入するからです。StandardScalerは中心化と再スケーリングだけを行うため、長い裾は残ります。生のままK-Meansへ入力すると、最初の分割を高額購入者と少額購入者の切り分けに使い、ほぼ価値階層を再発見します。追加で見つけるクラスタも、施策を実施するには小さすぎる外れ値の集まりになります。歪んだ特徴量へ log1p を適用すると（単純なルールとして、歪度が約1を超えるものを変換）、裾が圧縮されます。その結果、クラスタは支出の大きさではなく行動の形を反映し、均衡した行動可能なセグメントが現れます。付属データセットでは、K-Meansが3つの価値階層へ縮退するか、顧客基盤を均衡した同程度の規模の5つの行動群へ分けるかの違いになります。

Kの選択は、統計と判断の両方で行います。エルボー法は範囲を絞るのに役立ちますが、数を一つに決めることはほとんどありません。顧客データで最も鋭い折れ曲がりはK=3にあることが多く、通常はデシルとRFMですでに捉えた価値階層（高額、平均、休眠）を再現するだけです。価値ではなく行動で分けるには、実用的な範囲（多くの場合4〜8セグメント）まで進め、行動可能性で決めます。マーケティングチームが実際に異なる扱いをするセグメントを持つKを選びます。各セグメントに異なる行動を説明できなければ、セグメントが多すぎます。

付属データセットでは、K=5でセグメントが価値階層ではなく、施策概要として使えるものになります。表 2 がその結果です。構成比とプロフィール平均はNotebookから得ています（支出、来店回数、部門数は、セグメント内で平均した2年間の合計です）。名前と最後の2つの行動は、プロフィールのヒートマップに対する分析者の解釈であり、Notebookが読者へ残している手順です。

名前は略称であり、行全体が概要です。以下の行動可能性を確認するため、この表をマーケティングチームへ渡します。2つの行へ同じキャンペーンを行うなら、統合します。

数値によるクラスタリングでは、商品の意味が依然として平坦化されます。頻度、支出、最終購入からの期間、カテゴリーの幅、値引き依存度などを入力すると、購入する商品が大きく異なっても、2人の顧客が似て見える場合があります。その意味を捉えるには、商品テキストをセグメンテーションへ直接取り込みます。

BERTopicによる埋め込みベースのセグメンテーション

顧客が実際に何を購入するかを捉えるため、各顧客の購入履歴をテキストとして扱います。購入した商品の説明を一つの文字列（顧客ドキュメント）へ連結し、埋め込みモデルで密なベクトルへ変換します。この埋め込み空間では、誕生日用キャンドルとパーティー用の皿は近く、アンティークのティーポットは遠くに位置します。そのため、ベクトルをクラスタリングすると、購入量だけでなく購入の意味で顧客を分けられます。

例では、英国のギフト小売企業から得た約100万件の取引を含むUCI Online Retail IIデータセットを使います。自由記述の商品説明は、埋め込みモデルが読み取るものに適しています。パイプライン全体をBERTopicで実行します。

なぜBERTopicなのか？

このパイプラインを手作業で構築すると、ドキュメントを埋め込むSentenceTransformers、次元を削減するUMAP、クラスタリングするHDBSCAN、結果を読み取る独自コードという4つのライブラリをつなぐ必要があります。BERTopicは4つすべてを一つのAPIで包み、出力を使えるものにする機能も追加します。各セグメントの特徴的なキーワードを抽出するc-TF-IDF、HDBSCANが未割り当てとした顧客のための reduce_outliers()、再学習せずに新規顧客をスコアリングする transform()、名前をつけるための任意のLLM手順です。この節の残りでは、そのパイプラインに沿います。

顧客ドキュメントを構築する

たとえば、顧客のドキュメントは次のようになります。

red retrospot cake stand, party bunting, paper cups, birthday candles, cake cases

数値モデルには、この顧客が頻繁に購入する、または支出が多いとしか見えないかもしれません。埋め込みモデルには、パーティー用品とお祝い関連の購入という商品の意味が見えます。

取引ログをグループ化して連結することで作成します。

# Keep each customer's top-N products by revenue, then join the descriptions
prod_rev = (
    df.groupby(["CustomerID", "Description"])["Revenue"].sum()
    .reset_index()
    .sort_values(["CustomerID", "Revenue"], ascending=[True, False])
)
top_products = prod_rev.groupby("CustomerID").head(TOP_N)

customer_docs = (
    top_products.groupby("CustomerID")["Description"]
    .apply(lambda d: ", ".join(d))
    .reset_index(name="doc")
)

セグメントの品質を大きく左右する、3つの実務上の判断があります。

どの商品を入れるか。頻度または売上による購入上位N商品は、通常、購入履歴全体よりうまく機能します。完全なリストには一度限りの購入によるノイズが加わりますが、上位商品は顧客の実際のパターンを捉えます。

売上で重みづけするか。高額商品を1回、低額商品を1回含めるだけでは、顧客が何を重視するかを正しく表せない場合があります。売上による重みづけ（支出に比例して商品への言及を繰り返すこと）は、混合バスケットを持つ顧客のセグメントを明確にします。商品間の価格差が大きい場合は重みに上限を設けるか、対数支出による重みづけを使います。そうしなければ、一度の高級品購入がドキュメントを支配する可能性があります。

一般的な商品を除外する。「ギフトカード」「送料」や一般的なSKUはノイズです。すべてのセグメントに現れ、キーワードを薄めます。StockCodeのパターンで除外するか、小さな除外リストを管理します。この一つの手順だけで、意味のあるセグメントと意味のないセグメントが分かれることがよくあります。

多くの小売カタログでは、軽量な文埋め込みモデルで十分です。セグメントの品質は、どの埋め込みモデルを選ぶかより、顧客ドキュメントをどのように設計・検証するかに大きく依存します。Notebookでは再現性のためローカルのSentenceTransformersモデルを使いますが、同じワークフローでOpenAI embeddingsなどAPIベースの埋め込みモデルも利用できます。

出力を読み取る

この地図の背後にある当てはめは、1回の呼び出しだけです。ローカルの埋め込みモデルが各ドキュメントをベクトルへ変換し、BERTopicがクラスタリングとキーワード抽出を処理します。

from bertopic import BERTopic
from sentence_transformers import SentenceTransformer

embedding_model = SentenceTransformer("all-MiniLM-L6-v2")   # local, lightweight
embeddings = embedding_model.encode(customer_docs["doc"].tolist())

topic_model = BERTopic(embedding_model=embedding_model)
topics, probs = topic_model.fit_transform(
    customer_docs["doc"].tolist(), embeddings=embeddings
)

付属NotebookではUMAP、HDBSCAN、c-TF-IDFのサブモデルを明示的に設定しますが、これはデフォルト値を使った同じパイプラインです。その結果、各セグメントのキーワードによる特徴が得られます。

このパネルをマーケターへ渡すと、各群にどのカテゴリー、キャンペーン、クリエイティブが合うかをすぐに理解できるはずです。

一つのテーマが支配する場合

実際のカタログでは、顧客の大半を覆う一つの幅広いテーマと、周辺に明確なニッチの裾があることがよくあります。HDBSCANは両方を明らかにしますが、外れ値を減らした後、幅広いテーマが一つの巨大トピックへ膨らみ、一つのセグメントとして行動するには大きすぎる状態になります。修正は限定的に行います。巨大トピックの埋め込みだけにK-Meansを実行し、施策を実行できる規模の下位セグメントへ分けます。一方、小さなニッチトピックは発見事項として残します。「発見にはHDBSCAN、運用にはK-Means」というパターンを、顧客基盤全体ではなく、支配的なクラスタの内部へ適用します。付属Notebookは、どれかのトピックが顧客基盤の50%を超えると、自動的にこれを行います。

LLMによる命名の罠

LLMによる命名支援は、セグメントを実際以上に信頼できるものと感じさせます。無作為なものを含め、どのクラスタでもLLMへ渡して名前とペルソナを求めれば、洗練された説得力のある説明が返ります。クラスタに意味があるかどうかにかかわらず、物語はもっともらしく聞こえます。

2つの安全策があります。

  • LLMの説明を読む前に、キーワードの証拠を検証します。上位キーワードから自分で明確なテーマを見つけられなければ、LLMの名前は創作です。
  • マーケティングチームと名前をテストします。異なる名前をつけた2つのセグメントに、同じキャンペーン概要を書くのであれば、名前は情報ではなく飾りです。

付属Notebook： 完全に動作するコードを、それぞれの手法に適したデータセットを使う2つのNotebookへ分けています。

  • sec4.1_traditional_segmentation.ipynb：Dunnhumbyの「The Complete Journey」データセットで、デシル、RFM、K-Meansを実行します。CLVの章と同じデータセットなので、セグメント所属を引き継げます。GitHubで見る

セグメンテーションは優れているか？

優先順位に沿って3つを確認します。

行動可能性が最も重要です。マーケティングチームへセグメントのプロフィールを見せます。セグメントの各組について「異なるメッセージ、チャネル、オファー、頻度を使うか？」と尋ねます。「どちらにも同じことをする」と答えるなら、数式がどれほどきれいでも、そのセグメンテーションは行動可能ではありません。通常の原因は、すべてが平均的なセグメントです。隣のセグメントと統合するか、変数選択を見直します。

安定性。重複しない2つの期間でクラスタリングを再実行し、顧客の大半が同じセグメントに入ることを確認します。調整Rand指数（ARI）で数値化できます。期間間でセグメントを移る顧客が多すぎる場合、キャンペーンの基準として信頼できません。付属Notebookでは、セマンティック版でARIの計算、従来版で移行行列を示し、両方を確認します。

食料品データの移行行列では、再クラスタリングする代わりに、各年の売上五分位で顧客を順位づけします。上位五分位の70%、下位五分位の61%が翌年も同じ位置に残りますが、中央3群では約40%にすぎません。顧客基盤の中央では、セグメント割り当ての信頼性が最も低いため、それを使うキャンペーンには最も余裕が必要です。

規模。各セグメントは施策を実施できる十分な大きさが必要ですが、適切な最小値はビジネスとキャンペーンによって異なり、普遍的な下限はありません。大まかな目安として、意味のあるキャンペーンを実施できないほど小さいセグメントは避けます。幅広いターゲティングでは顧客基盤の約10%が目安になることが多い一方、本当に価値の高いニッチは意図的な例外にできます。実務では、多くの場合4〜8個ほどのセグメントで十分です。

セグメントは行動の違いから作りますが、そのセグメントへ割り当てるキャンペーンは依然としてテストが必要です。成功と判断する前に、A/Bテストの設計へ戻ってください。

手法早見表

要点

  • 行動からセグメントを作り、その後で人口統計を使って各群を説明し、到達可能にする。成果物はスライドではなく、CRMと広告プラットフォームで使えるsegment_idである。
  • 最初に実行可能性、次に安定性と規模を検証する。同じキャンペーンを受ける2つのセグメントは統合する。
  • 説得力のあるセグメント名は証拠ではない。LLMはランダムなクラスタを含め、どのクラスタにも名前を付けるため、ラベルを信頼する前に上位キーワードを自分で読む。
