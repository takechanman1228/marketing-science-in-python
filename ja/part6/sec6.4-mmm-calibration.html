6.4 実験によるMMMのキャリブレーション

Google Searchについて、いま2つの結果があります。Section 6.2のMMMは5チャネルすべてを扱いますが、Searchの推定は非常に不確かです。Section 6.3の実験はSearchを精密に測りましたが、測ったのはSearchだけです。

次の意思決定には、両方が必要です。Searchを削減すると予算が浮きます。それをどこに回すかを決めるには5チャネルすべてを比べる必要があり、それができるのはMMMだけです。そこで、実験がSearchについて明らかにしたことを、MMMに使わせます。

キャリブレーションとは何か

キャリブレーション（calibration）とは、実験の結果を使ってMMMを改善する作業です。ベイズのMMMでは、事前分布を通じて行います。あるチャネルについての実験の推定値をそのチャネルの事前分布にして、モデルをもう一度適合します（図 1）。再適合したモデルは2つの情報源を組み合わせます。テストしたチャネルについては主に実験に頼り、それ以外については履歴データに頼ります。

今回の事例は、これがなぜ必要かを示しています。テストの前に、ノートブックはSection 6.2のモデルに実験の結果を予測させました。8週間の30%のSearch削減のiROASです。モデルの予測は2.95で、90%区間は0.34から8.48でした。実験の測定値は1.50でした。

モデルの推定値は測定値の約2倍で、区間も意思決定を支えるには広すぎました。Search支出は3年間ほとんど動かなかったため、モデルはSearchについて事前分布以上の情報をほとんど持っていませんでした。キャリブレーションは、その情報をモデルに与えます。

キャリブレーションは3つのステップで進めます。本章の残りはこの順に沿っています。

  1. 実験が測ったのが、モデルのどの量なのかを特定する。
  2. 実験の結果を、その量の事前分布に変換する。
  3. モデルを再適合し、キャリブレーションしていないモデルと比べる。

ステップ1：平均ROAS、増分ROAS、限界ROAS

Meridianの事前分布は、特定の量に置きます。チャネルの平均ROASか、限界ROASのどちらかです。実験の結果は、実験が実際に測った量に置かなければなりません。そこで最初のステップでは、3種類のROASを区別します。

ある市場がSearchに毎週$100を使っているとします。3種類とも、売上の変化を支出の変化で割った値です。違うのは、対象とする支出の範囲です（図 2）。

  • 平均ROASは$0から$100まで、つまり現在の支出の全体が対象です。MMMが報告します。
  • 30%削減の増分ROASは$70から$100まで、つまりテストで減らした支出が対象です。実験が測りました。
  • 限界ROASは$100から$101まで、つまり次の1ドルが対象です。MMMが報告し、オプティマイザーはこれに基づいて配分します。

飽和する反応曲線では、最初の1ドルのほうが最後の1ドルより多く稼ぎます。そのため、3つのうち平均ROASが最も高くなります。削減のiROASと限界ROASは、どちらも曲線の上端についての値なので、互いに近く、平均より低くなります。

実験が測ったのは、30%削減のiROASです。これは限界ROASに最も近いので、実験の結果は限界ROASの事前分布に反映します。

置き場所を間違えるとどうなるか。 Meridianの既定の事前分布roi_mは、平均ROASに置かれます。実験の結果をそこに置くと、モデルは支出の最後の30%で測った数値を、支出全体のリターンとして扱います。ノートブックは比較のためにこの版も適合します。この版はSearchの平均ROASを1.96と推定しますが、データ上の真値は3.30で、約40%低すぎます。平均ROASの事前分布が正しい選択になるのは、チャネルを完全に止める実験の場合だけです。

ステップ2：実験を事前分布に変換する

media_prior_type="mroi"を指定すると、Meridianは事前分布を限界ROASに置きます。実験のiROASは限界ROASに近いものの、同じではありません。実験が対象としたのは、8市場で8週間行った30%の削減です。限界ROASは、全国での次の1ドルについての値で、後から発生する売上も含みます。この違いのそれぞれに、調整が必要です（表 1）。

期間は、事前分布の中心を引き上げます。8週目に行った削減は、測定を終えた後の9週目と10週目にも売上を減らします。Searchの半減期は1週間なので、効果の約12%が測定期間の外に出ます。TV/CTVのような減衰の遅いチャネルでは、8週間の測定期間は効果の約半分を取りこぼします。

支出スケールと変換の不確実性は、事前分布の幅を広げます。テストが対象としたのは全国のSearch支出の約5分の1なので、チャネル全体に当てはめると結果の確かさは下がります。変換の不確実性は、中心の15%にあたる最小限の幅を加えます。30%の削減は、次の1ドルの近似にすぎないからです。

3つの調整を経て、実験の1.50（標準誤差0.257）は、Searchの限界ROASについての、平均1.71、標準偏差0.69の事前分布になります。事前分布は、意図して実験より広くしてあります。実験は、テストした8市場については精密ですが、全国の限界ROASについてはそこまで精密ではありません。事前分布が表すのは後者です。

期間と支出スケールは、実験を事前分布に変換する方法としてMeridianが文書化している調整に従っています。変換の不確実性は本書で加えたものです。Meridianの手順は支出ゼロとの比較による実験を想定していますが、今回の実験は部分的な削減だったからです。

# Imports as in Section 6.2. Both helpers are defined in notebook Step 15.
center, se = calibrated_prior_moments(
    estimate=1.500, standard_error=0.257,
    capture_proportion=0.8756,       # duration: share of the effect inside 8 weeks
    # taus: duration, spend scale, recency (zero, because the test is recent)
    taus=[0.142, 3.606, 0.000],
    translation_share=0.15,          # translation uncertainty
)                                    # -> center 1.71, SE 0.69
search_mu, search_sigma = lognormal_from_mean_std(center, se)

# mroi_mu, mroi_sigma: one entry per channel. Search gets search_mu and
# search_sigma; the other four keep a weak prior (notebook Step 15).
calibrated_prior = prior_distribution.PriorDistribution(
    mroi_m=tfp.distributions.LogNormal(
        loc=tf.constant(mroi_mu, dtype=tf.float32),
        scale=tf.constant(mroi_sigma, dtype=tf.float32),
        name=constants.MROI_M,
    ),
    # adstock and saturation priors from Section 6.2
    alpha_m=prior.alpha_m, ec_m=prior.ec_m,
)

# Same lag and holdout weeks as Section 6.2, so the only change is the prior.
calibrated_spec = spec.ModelSpec(
    prior=calibrated_prior, media_prior_type="mroi", max_lag=12,
    adstock_decay_spec="geometric", holdout_id=holdout_id,
)

残り4チャネルは、弱い事前分布のままにします。そのうえで、同じデータ、同じ設定でモデルをもう一度適合します。

ステップ3：キャリブレーションの前後でモデルを比べる

実験によって何が変わったかを見るために、Searchの事前分布だけが違う2つの適合を比べます。どちらも限界ROASの事前分布を使います。1つ目はすべてのチャネルに弱い事前分布を置き、2つ目はSearchに実験に基づく事前分布を置きます（表 2）。ここではSection 6.2のモデルを基準にしません。あのモデルは平均ROASの事前分布を使っており、比べると2つの変更が混ざってしまうからです。

推定値はほとんど変わりませんでした。限界ROASは、実験なしで1.95、実験ありで2.00です。大きく変わったのは不確実性です。90%区間は[0.18, 7.03]から[0.93, 3.63]になり、幅は半分以下です。

これによって、モデルがSearchについて使えるようになります。Section 6.2では、区間が広すぎたためSearchの推奨を保留にしました。キャリブレーション後の区間は、その基準を満たします。

Searchについての予算の推奨は、どちらの適合でも同じです。30%の削減で、オプティマイザーに許された最大幅です（図 3）。キャリブレーションは方向を変えず、その推奨を支えられるだけの精度をモデルに与えました。

残りのチャネルについて、キャリブレーション後のモデルはOOHとMetaの30%増額、TV/CTVの16.4%削減、TikTokの11.4%削減を推奨します。TV/CTVとTikTokの数値は、30.0%と0.2%の削減だったSection 6.2とは異なります。図 3 は、この変化がどこから来たかを示しています。変化は実験なしの適合ですでに現れているので、原因は限界ROASの事前分布への切り替えです。

キャリブレーション後の計画を使う

キャリブレーション後の計画には2種類の推奨が含まれており、扱い方が違います。

Searchの削減はテスト済みなので、実行に進めます。 段階的に展開します。削減をより多くの市場に広げ、無作為に選んだ一部の市場を従来の予算のまま対照として残し、iROASが2.50を下回り続けることを確かめます。

モデルは、Searchの削減で浮いた予算をOOHとMetaに回し、それぞれ30%増額することを提案しています。どちらかを、無作為化したマッチドペアで30%増額し、開始前にモデルのiROASの予測を記録し、その結果でもう一度キャリブレーションします。一般に、支出が大きく、モデルの区間が広く、結果によって計画が変わりうるチャネルをテストします。

プラットフォームのダッシュボードが答えるのは、もっと狭い問いです。 Searchのダッシュボードは、アトリビューションに基づくROASを報告します。Search広告のクリックに続くすべての注文を数え、広告がなくても発生した注文も含みます。そのため、その数値は通常、実験のiROASより高くなります。ダッシュボードはSearchの中でキーワードやクリエイティブを比べるために使い、Searchの予算を決めるには実験とMMMを使います。

これがPart 6全体の進め方です。MMMが全チャネルの予算を提案します。実験は、不確かで、かつ影響の大きい推奨をテストします。キャリブレーションが実験の結果をモデルに戻し、次のテストでこのサイクルを繰り返します。

重要なポイント

  • キャリブレーションは、実験の結果をMMMの事前分布として使う。これによりモデルは、テストしたチャネルについては実験に、それ以外については履歴データに頼る。
  • 結果は、実験が測った量に置く。部分的な削減は限界ROASに最も近く、平均ROASに置くと、ここでは推定値が約40%低くなった。
  • 事前分布は実験より広くする。後の週、テストしていない市場、部分的な削減と次の1ドルの差を見込むためである。キャリブレーションはSearchの推定値をほとんど動かさず、区間を大きく狭めた。
