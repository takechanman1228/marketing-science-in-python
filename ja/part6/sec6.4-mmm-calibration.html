6.4 実験によるMMMの較正

日本語版について
このページは英語版 Marketing Science in Python のAI翻訳です。英語版を正本とし、差異がある場合は英語版を優先してください。コード、Notebook、画像内の文字は英語のままです。 英語版を読む

地域実験を行う前に、MMMはGoogle Searchの30%削減が何を失うかを予測していた。削減1ドルあたり$2.95の売上、90%信用区間は0.34から8.48である。Section 6.3の実験は1.500を測り、95%信頼区間は0.892から2.109だった。モデルはチャネル全体の価値をおおむね正しく捉えていたが、削減のコストは約2倍高く見積もっており、区間はどちらにせよ行動に移すには広すぎた。どちらも驚くことではない。Search支出は3年間の履歴でほとんど動かなかったため、モデルのSearch推定値の大部分は出発点の事前分布のままであり、この実験がこのチャネルに関する初めての因果的証拠である。

較正は、その証拠をモデルへ入れる作業である。実験が測ったのは1つのチャネルの1つの運用点、1つの期間だが、Section 6.2のモデルは5チャネルの予算を決めなければならない。そこで実験結果を事前分布へ変換し、再適合し、推奨が変わるかを確かめる。目的はモデルを実験に同意させることではない。よりよい証拠が意思決定を変えるか、変えないならなぜかを知ることである。この例の成果は売上なので、MeridianのROIは数値上は売上ROASになる。本文ではROASと呼び、コードではMeridianの名称を保つ。

付属ノートブック： sec6.2_6.4_mmm_meridian.ipynbはSection 6.2と共通である。Step 14〜18では、テストに対するモデル自身の予測を記録し、実験推定値を事前分布へ変換し、モデルを再適合し、予算を再最適化する。

証拠をモデルの量に合わせる

実験が測ったのは、1つの支出ブロックのリターンである。Searchの予算を8週間、100%から70%へ落としたとき、1ドルあたりいくらの売上を失ったか、という量だ。モデルは同じチャネルについて、別の2つのリターンを報告する。平均ROASは、Searchの総増分売上を総支出で割った値で、ゼロから平均したリターンである。限界ROASは、現在の支出における反応曲線の傾き、つまり次の1ドルのリターンである。飽和曲線では最初の1ドルほどよく働くため、曲線が曲がり始めた場所では平均ROASが限界ROASを上回る（図 2）。テストした削減は支出の上位30%にわたって曲線を平均するため、限界リターンに近く、平均リターンよりかなり低い値になる。

Meridianの既定の事前分布roi_mは平均ROASに置かれる。期間補正後の推定値1.71をその事前分布に置けば、モデルは従う。ノートブックで試すと、事後の平均ROASは1.96になり、埋め込んだ真値3.30と合わない。モデルは今や、ゼロからのリターンが40%低すぎる曲線でSearchを説明することを強いられている。ここでは限界リターンとテストした削減の予測は、それぞれ1.59と1.44で、なお真値の近くに着地する。Searchの範囲の上端では曲線がほぼ直線なので、狂うのは平均という量だからだ。より曲がったチャネルなら、局所的な読みも一緒に狂う。限界リターンが平均のおよそ4分の1しかないTikTokで同じ置き換えをすれば、モデルは4倍近く間違う。測定値は、それに対応するパラメータに置く。

実験を事前分布へ変換する

Meridianでは、media_prior_type="mroi"を指定して、事前分布を限界ROIに置ける。このパラメータは支出を1%増やしたときのリターンである。実験が測ったのは8週間の30%削減なので、パラメータを観測するのではなく、近似的な変換を通じて事前分布に情報を与える。曲線の形状、キャリーオーバー、そして8市場から全国への転移についての仮定が、結果の一部として残る。Searchではブロックと傾きは近く、1.50に対して埋め込んだ真値は1.57である。TV/CTVのような減衰の遅いチャネルではそうならないことを、Section 6.5が示す。

この変換は3つの部分からなる。期間は、テスト期間が取りこぼしたキャリーオーバーの分だけ中心を補正する。8週目に行った削減は9週目と10週目にも売上を失わせるため、Searchの半減期が1週間でも、8週間続けた削減の効果の約12%はウィンドウの後に発生し、中心は1.50から1.71へ動く。この割合は、毎週同じ変化量と線形のキャリーオーバー重みを仮定した近似であり、飽和と実際の支出経路によって変わりうる。TV/CTVのような減衰の遅いチャネルなら、補正は数倍大きくなる。支出スケールは事前分布の幅を広げる。8つのテスト市場は全国の支出率の約5分の1で稼働しており、テストがチャネルの規模から離れるほど、その結果が他の地域にも当てはまると仮定しにくくなる。この項が標準誤差を0.257から0.64へ広げ、後述の変換の不確実性がそれを0.69にする。実験自体の精度は十分だった。事前分布を広げたのは、8市場がチャネル全体の5分の1にすぎないという事実である。ノートブックは各項を出力し、ここではほとんど効かない小さな2項も併せて示す。

変換の不確実性が3つ目の部分で、これはGoogleの指針ではなく私たち自身のものである。30%のブロックと1%の傾きの間の隔たりはモデル化上の仮定なので、中心に対する一定の割合、ここでは15%を幅に加える。こうすれば、非常に精密な実験でも、傾きを正確に知っていると主張する事前分布は生まれない。他の4チャネルは弱い限界ROI事前分布LogNormal(-0.49, 0.90)を保つ。これはSection 6.2の弱いROAS事前分布を限界スケールで表し直したものである。これ以上平坦にしてはいけない。飽和曲線上で限界ROIに拡散的な事前分布を置くと平均ROIの上限がなくなり、未較正のチャネルは使いものにならない区間を返してくる。

import numpy as np
import tensorflow as tf
import tensorflow_probability as tfp
from meridian import constants
from meridian.model import prior_distribution, spec

channels = list(data.media_channel.values)
target = channels.index("Google Search")

# Weak marginal-ROI prior for every channel, then the experiment on Search.
mroi_mu = np.full(len(channels), 0.2 + np.log(0.5))
mroi_sigma = np.full(len(channels), 0.9)
mroi_mu[target], mroi_sigma[target] = 0.4635, 0.3877   # centre 1.71, SE 0.69, from the translation above

prior = prior_distribution.PriorDistribution(
    mroi_m=tfp.distributions.LogNormal(
        loc=tf.constant(mroi_mu, dtype=tf.float32),
        scale=tf.constant(mroi_sigma, dtype=tf.float32),
        name=constants.MROI_M,
    ),
    alpha_m=prior.alpha_m,        # Section 6.2's adstock prior, reused as is
    ec_m=prior.ec_m,              # Section 6.2's saturation prior, reused as is
)

# Same lag, same holdout weeks as Section 6.2, so the only change is the prior.
model_spec = spec.ModelSpec(prior=prior, media_prior_type="mroi", max_lag=12,
                            adstock_decay_spec="geometric", holdout_id=holdout_id)

そのうえで、ROASの表を後から書き換えるのではなく、モデルを再適合する。較正したチャネルは証拠へ近づくはずだが、正確に1.500へ着地する必要はない。尤度、曲線、事前分布のすべてが結果に関与するからだ。1つのチャネルを狭めると、相関する他のチャネルとの間で寄与の配分も変わるため、再適合後は全チャネルと全体の適合を読む。

何が変わったか？

公平に比較するため、3つの適合を使う。基準となるSection 6.2のモデル、実験なしで限界ROI事前分布へ切り替えた対照適合、そして較正後の適合である。地域テストを見たのは最後の1つだけなので、最後の2列の差は証拠そのものであり、それ以外の要因を含まない。最初の2列の差は事前分布の指定の変更である。最初の行は、支出の対比とウィンドウの長さを実験に揃えている。カレンダー上の日付と地理的な範囲は依然として異なる。

変わったのは幅である。対照適合と比べると、較正はSearchの限界リターンを1.95から2.00へ動かし（埋め込んだ真値は1.57）、相対半幅を1.76から0.67へ縮めた。テストした削減に対するモデル予測は、測定値1.50に対して1.75から1.82へ動いた。どちらの点推定値も本題ではない。本題は区間である。図 3 は、それを曲線に沿って示す。基準適合は3付近を読み、そのバンドは1桁分の幅にわたる。対照適合は2未満を読み、バンドは同じ幅である。較正後の曲線は、3分の1の幅のバンドで実験の区間を通る。基準適合と較正後の適合の間のより大きな差は、実験ではなく主に事前分布の指定の変更によるもので、対照の列があるのはそのためである。

わからないままのことも、名指ししておく価値がある。平均ROASの行は、埋め込んだ真値3.30に対して2.82に着地し、区間は5.3まで届く。実験はゼロからのリターンを一度も測っていないので、この行はモデルの外挿であって証拠ではない。Section 6.2の幅ルールは今や満たされるが、そのルールが確認するのは精度であって収益性ではない。削減そのものはSection 6.3の閾値で決着しており、解放された予算がOOHとMetaへ向かうのは、両者の限界リターンの区間が2.6と3.6から始まり、Searchの推定値2.0を上回るからである。ただし、Searchの区間上限は上回らない。Searchはすべての列で−30%の下限にとどまり（図 4）、TV/CTVとTikTokはわずかに動くが、その大半は基準適合と対照適合の間、つまり実験ではなく事前分布の指定によるものである。市場でクラスタ化した狭い方の幅で同じ較正を行うと、限界推定値は1.85、半幅は0.48になり、配分はやはり動かない。したがって、実験は所定の利益率とウィンドウの下でテストした削減を支持し、較正はその証拠を配分モデルへ運ぶ。そしてモデルが提案する再配分は、反応曲線、8市場から全国への転移、そしてオプティマイザーには見えない事業上の制約を条件としたままである。

較正後の計画で行動する前に

レビュー会議で問うべき順番に、4つの問いを示す。

  1. 推定対象の整合性。 実験は、同じ成果、同じ対比、そして推奨が実際に訪れる運用点を測っているか。
  2. 実験の信頼性。 意思決定に必要な検出力があり、設計どおり配信され、波及とカレンダーショックがなかったか。
  3. モデルの健全性。 再適合後も、適合、反応曲線、他チャネルは妥当か。
  4. 意思決定の安定性。 正当化できる変換幅の範囲で、推奨行動は維持されるか。その間で反転するなら、点推定値が何を示しても証拠は意思決定を解決していない。

データ品質と一般的なモデル検証はSection 6.2で扱っており、ここで繰り返す必要はない。

すべてのチャネルで実験する必要はない。支出が重要で、モデルの区間が広く、結果が行動を変えうる場所をテストする。Section 6.2の意思決定カードのように、各テストの前にモデルの予測を記録する。次の配分の前にモデルを更新し、次の不一致に次のテストを選ばせる。

重要なポイント

  • 較正の前に推定対象を一致させる。1つの支出ブロックの測定値は、近似的な変換を通じて限界パラメータに情報を与え、その変換に含まれる仮定は幅として一緒に運ばれる。
  • モデル全体を再適合し、対照適合を残す。証拠の効果を、事前分布の指定の変更と切り分けるためである。ここでは、証拠はSearchの推定値をほとんど動かさず、区間を3分の2縮めた。
  • 較正は、それが何を支持できるようにするかで判断する。実験が削減を決め、較正はそれを配分モデルへ運んだ。そのモデルの再配分は、依然として曲線、転移の仮定、事業上の制約に依存している。
