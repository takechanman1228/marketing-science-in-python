3.3 準実験

日本語版について
このページは英語版 Marketing Science in Python のAI翻訳です。英語版を正本とし、差異がある場合は英語版を優先してください。コード、Notebook、画像内の文字は英語のままです。 英語版を読む

A/Bテストは、原因と結果を測定するためのゴールドスタンダードです。誰が処置を受けるかを無作為化すれば、対照群から処置がない場合に何が起きたかが分かります。しかし、いつでも実施できるわけではありません。Section 3.1で扱ったように、A/Bテストを選べない理由は数多くあります。

無作為化できない場合は、準実験を使います。 準実験は、無作為割り当てを行わずに原因と結果を推定します。閾値、一部の単位を対象外にした展開、開始日など、ビジネスプロセスが残した比較を利用します。最後の点には注意が必要です。無作為でない展開が、自動的に利用可能な準実験になるわけではありません。仮定を説明できる比較が残っている必要があり、この章の各デザインには、説明しなければならない仮定があります。

この章では、回帰不連続デザイン（RDD）、差の差法（DiD）、合成コントロールという3つのデザインを扱います。いずれも、ディスプレイを導入しなかった店舗からなる対照群や、一つの比較対象へ合成する店舗のプールなど、比較対象となる非処置の単位が必要です。4つ目のデザインであるCausalImpactは、非処置の単位が一つもない場合に使います。これは次の章で扱います。

状況に合うデザインはどれか？

4つのデザインから選ぶのは大変で、名称だけではどれが必要か分かりません。そこで、すべてを一つの具体的な問題へ当てはめます。ある小売企業には100店舗があります。新しい店頭ディスプレイを展開し、それがカテゴリー売上へ与えた影響を知りたいとします。

最初の問いは常に同じです。ディスプレイは無作為に割り当てられたか？無作為なら、非処置店舗が対照群となり、Section 3.2へ戻ります。無作為でなければ、割り当て方法によってデザインが決まります。

どの行にも同じ100店舗があります。変わるのはディスプレイの割り当て方であり、それによってデザインと必要なデータの両方が決まります。RDDには割り当て変数、DiDには導入前後のパネル、合成コントロールには長い事前期間と非処置店舗のプールが必要です。無作為に選ばれた50店舗と営業チームが選んだ50店舗は同じ表を作り得ますが、実験なのは前者だけです。これが章全体のルールです。割り当てがデザインを決め、その後、データによってデザインの信頼性が決まります。

この表は、一つの小売企業が持つ5つの選択肢です。図 1 は、これをあらゆる展開に使えるルーターへ変えます。2つの「はい／いいえ」の質問に答えた後、残っている非処置データの量に応じて選択します。

4つのデザインは、互いに無関係な4つの工夫でもありません。その一つであるRDDは、閾値だけを使います。残りの3つは、はしごを形成します。DiDは対照店舗のトレンドを借ります。合成コントロールは、単独で適切な店舗がない場合に、対照店舗を合成してより良い比較対象を作ります。CausalImpactは、対照店舗が一つもない場合に比較対象を予測します。段を上るほど、モデルへの依存が強くなります。この章では、RDDとはしごの最初の2段を扱います。

回帰不連続デザイン（RDD）

中心となる考え方： 閾値のすぐ周辺では、割り当てを無作為とみなせる。

表 1 の2行目から始めます。営業チームは店舗を選ぶ代わりに、「年間売上が$1Mを超える全店舗へ新しいディスプレイを導入する」というルールを定めました。構造上、パイロット店舗は規模の大きい店舗になります。残りの店舗と比較しても、規模が大きいことの影響を測るだけです。

しかし、境界付近の店舗を見てください。売上$1.02Mの店舗と$0.98Mの店舗は、規模がほぼ同じで、似た買い物客に対応し、同様のプロモーションを実施しています。$1Mのどちら側になったかは、コイントスに近いものです。RDDは、そのように扱います。閾値のわずか上とわずか下のアウトカムを比較し、$1Mでカテゴリー売上が跳ね上がれば、その跳びがディスプレイの効果です。同じ論理は顧客にも使えます。過去の支出が$500以上の顧客へクーポンを渡すなら、$502を支出した顧客と$498を支出した顧客を比較します。

RDDが機能しない場合

RDDは閾値付近の単位しか使わないため、その周辺に多数の単位が必要です。100店舗のうち、$1Mの数パーセント以内にある店舗が10店ほどなら、両側に線を当てはめ、ノイズを上回る跳びを確認するには少なすぎます。$500付近に20,000人の顧客がいるなら、少なすぎることはありません。そのため、マーケティングにおけるRDDは、過去の支出に基づくクーポンやポイント、営業活動のリードスコア閾値など、主に顧客単位で使われます。図 2 は、その例を示しています。

さらに2つの限界があります。効果は局所的です。$500での跳びから分かるのは、約$500を支出する顧客に対するクーポンの効果であり、$5,000を支出する顧客への効果ではありません。また、各単位が自ら境界を越えられてはいけません。リワードプログラムで$1,000に達すると次のランクへ上がり、顧客がそれを知っていれば、12月に追加でもう一度購入して境界を越える人がいます。店舗責任者が$1M達成でボーナスを得るなら、11月時点で$0.97Mの店舗は、$1.01Mで終える方法を見つけます。いずれの場合も、閾値のわずか上にいるのは、より努力した単位であり、RDDはそれを処置の効果と読み取ります。割り当て変数のヒストグラムで閾値のすぐ上に山があれば、それが兆候です。そのような閾値ではRDDを使えません。

差の差法（DiD）

中心となる考え方： 水準ではなく変化を比較する。対照群の時間変化を、処置群に処置がなかった場合の変化として用いる。

次に、表 1 の3行目を見ます。営業チームが新しいディスプレイを導入する50店舗を選び、比較可能な50店舗は標準の棚割りを維持しました。両群について、展開前後の店舗当たりカテゴリー売上があります。

パイロット店舗の売上は$42kから$48kへ増えました。では、ディスプレイには店舗当たり$6kの価値があるのでしょうか？

おそらく違います。比較店舗は、ディスプレイがないにもかかわらず、$40kから$43kへ増えました。季節性、来店客数、競合の欠品など、何かがカテゴリー全体を約$3k押し上げました。パイロット店舗だけで前後を比較すると、その市場成長をディスプレイの効果として計上してしまいます。

では、展開後に2群を比較します。$48kと$43kの差は$5kです。これが効果でしょうか？

これも違います。何かが起きる前から、パイロット店舗は$42k、比較店舗は$40kで、すでに$2k上回っていました。営業チームは無作為に選んでいないため、導入後に処置群と対照群を比較すると、その先行分をディスプレイの効果として計上します。

単純な比較は、それぞれ異なる交絡によって失敗します。導入前後の比較は共通の時間トレンドを拾います。処置群と対照群の比較は、群間にもともとあった差を拾います。2つの差の差を取れば、どちらも相殺されます。

店舗群 導入前 導入後 変化
パイロット店舗 $42k $48k +$6k
比較店舗 $40k $43k +$3k
DiD推定値 +$3k

パイロット店舗は$6k、比較店舗は$3k成長し、その差は$3kです。別の計算でも同じ答えになります。導入後の$5kの差から、導入前の$2kの差を引きます。これが差の差法です。 共通トレンドと、群間に固定的に存在する差が相殺されます。残るのは、比較店舗では説明できないパイロット店舗の変化です。

コードでは、この推定値は2つの差だけで計算できます。

import pandas as pd

did = pd.DataFrame({
    "group":  ["Pilot stores", "Comparison stores"],
    "before": [42, 40],   # category sales per store, $k
    "after":  [48, 43],
})
did["change"] = did["after"] - did["before"]              # +6 and +3
did_estimate = did.loc[0, "change"] - did.loc[1, "change"]
print(f"DiD estimate: ${did_estimate}k")                  # DiD estimate: $3k

DiDは、店頭ディスプレイのパイロット、棚割り変更、地域別プロモーション展開、特定市場での価格変更、一方のプラットフォームへ先行導入したアプリ機能など、マーケティングにおける「変わった単位と変わらなかった単位がある」状況の多くに適しています。

平行トレンドの仮定

DiDは平行トレンド（共通トレンドとも呼ばれます）の仮定に基づきます。処置がなければ、両群は同じトレンドに従っていたという仮定です。水準ではなくトレンドです。パイロット店舗のように、群の売上水準が異なるところから始まっても構いません。重要なのは、展開後の比較群の変化が、パイロット店舗が独力で示したはずの変化を公平に代替することです。

ディスプレイがないパイロット店舗は観察できないため、この仮定を完全に検証することはできません。しかし、展開前の期間は確認できます。

両群を時系列でプロットし、ディスプレイ導入前の部分を見ます。2本の線が一緒に動いていれば、DiDには信頼性があります。きれいな事前トレンドは信頼性の確認であり、証明ではありませんが、誰もが求める確認です。

DiDが機能しない場合

営業チームが成長の勢いを基準に選んだ場合、DiDは機能しません。すでに成長の速い店舗を選んでいたら、2群はトレンドを共有せず、DiD推定値は、どちらにしても起きていた成長を効果として計上します。事前期間のプロットを見ると、ディスプレイ導入前から線が乖離しています。その場合はDiDを無理に使わず、群をより慎重にマッチングする、比較店舗へ重みづけする、または合成コントロールへ移ります。

回帰でDiDを推定する

2×2の表が考え方を示しています。しかし、2つの理由から、実際の報告にそのまま使うものではありません。標準誤差がないため、+$3kがゼロと区別できるかを判断できません。また、実際のデータは2期間ではなく、100店舗の24カ月分の売上です。回帰版なら両方に対応できます。店舗・月ごとに1行とし、各店舗の固定効果、各月の固定効果、導入後期間の処置店舗に対する一つの交互作用項を入れます。店舗効果は店舗間の固定的な差をすべて吸収します。月効果は、その月に全店舗へ影響したトレンドとショックをすべて吸収します。交互作用項がDiD推定値そのものです。

import statsmodels.formula.api as smf

# df: one row per store-month (store_id, period, treated, post, category_sales)
model = smf.ols(
    "category_sales ~ C(store_id) + C(period) + treated:post",
    data=df,
).fit(cov_type="cluster", cov_kwds={"groups": df["store_id"]})

coef, se = model.params["treated:post"], model.bse["treated:post"]
print(f"DiD estimate: {coef:.2f} (SE {se:.2f})")   # DiD estimate: 3.02 (SE 0.04)

標準誤差を店舗単位でクラスタリングすることで、各店舗の反復測定に対応します。同じ回帰で事前トレンドも確認できます。treated:post を各月の treated × 月の項へ置き換え、展開前の項がゼロに近いことを確認します。付属Notebookでは、完全なパネルとこの確認を一通り実行します。

合成コントロール

中心となる考え方： 単独で一致する対照単位がない場合、複数を組み合わせて作る。

DiDが機能したのは、50の対照店舗から信頼できるトレンドを借りられたからです。次に、表 1 の4行目を見ます。ニューヨーク店だけにディスプレイが導入されました。残り99店舗のうち、どれが適切な比較対象でしょうか。規模、カテゴリー構成、地域の競争環境が異なり、単独でニューヨーク店の代わりになる説得力のある店舗はありません。

合成コントロールは一つを選びません。残り99店舗をドナープールとして扱い、その加重合成から「合成ニューヨーク」を作ります。ディスプレイ導入前の合成系列がニューヨークの売上をできる限り近く追うよう、重みを選びます。付属Notebookでは、ボストン店36%、フィラデルフィア店28%、シカゴ店22%、残り数パーセントをほかの4店舗へ配分した合成になります。ディスプレイ導入後、実際のニューヨーク店と合成された双子との差が推定効果です。

一つの単位が処置を受け、多数の類似単位が受けない場合に自然なデザインです。1店舗だけの改装、1都市圏だけの屋外広告キャンペーン、1つのSKUだけの価格変更と、ドナーとなる同系統のSKUなどです。こうした地域単位のデザインは、Section 6.3で地域実験の頑健性確認として、Section 6.4でメディアミックスモデルのキャリブレーション基準として再登場します。

合成コントロールが機能しない場合

信頼性を確認するのは、事前期間の適合です。99店舗をどのように合成してもディスプレイ導入前のニューヨーク店の履歴を再現できないなら、導入後の差を信頼してはいけません。ドナーが処置を受けていないことも必要です。ニューヨークのディスプレイはシカゴの売上を動かしませんが、ニューヨークのテレビキャンペーンはニュージャージーへ届く可能性があります。処置を受けたドナーは、合成された双子を処置の経路へ引き寄せます。また、顧客一人には使えません。一人の顧客の週次支出は大半がゼロとノイズであり、ほかの顧客をどう合成しても追跡できません。顧客単位の問いには多数の顧客が必要であり、それはDiDまたはRDDの領域です。

対照群がない場合

DiDは対照店舗からトレンドを借りました。合成コントロールは、単独で適切な店舗がない場合に対照店舗を合成しました。RDDは、境界のわずか下とわずか上の店舗を比較しました。3つとも、施策が届かなかった単位から比較対象を借ります。そのため、施策が全員へ届いた場合には役立ちません。

  • 新しいディスプレイが、同じ日に全100店舗へ導入された。
  • キャンペーンが一部ではなく、すべての地域で実施された。
  • クーポンがすべての顧客へ送られた。

比較できる非処置の店舗、地域、顧客がありません。そのため、比較対象を予測する必要があります。施策前に対象系列がどのように動いていたか、そして施策が影響できないほかの系列が施策後にどのように動いたかを使います。これがはしごの最後の段であるCausalImpactであり、次の章で扱います。

要点

  • 割り当てがデザインを決める。無作為化すればA/Bテスト、閾値があればRDDとなる。それ以外ではDiDから合成コントロール、CausalImpactへとはしごを上り、各段でモデルへの依存が強くなる。
  • 準実験の信頼性は、識別仮定の信頼性を超えない。事前トレンド図や事前期間の適合は弱い設計を露呈させられるが、通過は信頼性確認であって証明ではない。
