3.2 A/Bテストの設計

日本語版について
このページは英語版 Marketing Science in Python のAI翻訳です。英語版を正本とし、差異がある場合は英語版を優先してください。コード、Notebook、画像内の文字は英語のままです。 英語版を読む

チームは新しい決済ページについて、2週間のA/Bテストを終えたところです。全員が結果を待ち望んでいます。そして、次の数値が届きました。

パターン ユーザー数 コンバージョン数 CVR
対照群 5,000 115 2.30%
処置群 5,000 127 2.54%

処置群は少し良く見え、0.24ポイントのリフトがあります。しかし、2標本比率のz検定ではp値が0.43になります。

import numpy as np
from statsmodels.stats.proportion import proportions_ztest

conversions = np.array([127, 115])   # treatment, control
users = np.array([5000, 5000])
stat, p_value = proportions_ztest(conversions, users, alternative="two-sided")
print(f"p-value: {p_value:.2f}")     # 0.43

そこでチームは「有意ではない。再設計には効果がない。次へ進もう」と言います。その結論はデータに裏づけられていません。p値が0.43であることは、効果がないという意味ではありません。テストでは、小さな効果と偶然のノイズを区別できなかったという意味です。処置群の方が本当に良い可能性はありますが、データからは判断できません。「効果がない」と「分からない」の違いは、テストに十分な検出力があったかどうかで決まります。

統計的検出力

統計的検出力とは、特定の大きさの効果が本当に存在する場合に、テストがその効果を検出する確率です。多くのチームは検出力80%を目指しますが、その大きさの効果を見逃す確率が依然として20%残ります。

同じA/Bテストを何度も繰り返す場面を想像してください。再設計に真の効果がなければ、推定リフトはゼロの周辺で変動します。再設計が本当にコンバージョンを改善するなら、推定リフトは真のリフトの周辺で変動します。検出力とは、テスト結果がゼロから十分に離れ、効果を検出できる確率です。

購入のような低コンバージョンのイベント（たとえばコンバージョン率2%）で0.5ポイントのリフトを検出するには、各群に何千人ものユーザーが必要ですが、多くのチームはそれよりはるかに少ない人数で実施します。多くのチームが過小評価するのはこの点です。小さなリフトの検出には、直感で考えるよりはるかに多くのトラフィックが必要です。

サンプルサイズを計算する

実際には何人のユーザーが必要でしょうか。テストの規模を決めるには、4つの入力が必要です。ベースラインのコンバージョン率、検出する価値のある最小のリフト（MDE）、許容する偽陽性率（\(\alpha\)、通常0.05）、目標とする検出力（\(1 - \beta\)、通常0.80）です。

重要な直感は次のとおりです。

\[n \propto \frac{1}{\text{MDE}^2}\]

半分のリフトを検出したければ、およそ4倍のユーザーが必要です。Pythonでは次のように計算します。

from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

baseline_cvr = 0.02
target_cvr = 0.025
effect_size = abs(proportion_effectsize(target_cvr, baseline_cvr))

analysis = NormalIndPower()
required_n = analysis.solve_power(
    effect_size=effect_size,
    alpha=0.05,
    power=0.80,
    ratio=1,
    alternative="two-sided",
)
print(f"Required sample size per group: {required_n:.0f}")  # ~13,800

2%のベースラインから2.5%へのリフトを検出するには、各群に約13,800人が必要です。実務では切り上げ、トラッキングの欠損や除外ユーザー分を上乗せするため、約15,000人を計画します。

この曲線から、重要な教訓が分かります。サンプルサイズは線形に増えるのではなく、対象とするリフトが小さくなるにつれて急増します。そのため、コンバージョン率の低い指標における小さな改善は、測定コストが高くなります。

開始前に決める

テストを開始する前に、4つの決定事項を書き出します。

  1. 主要指標：どの指標でテスト結果を判断するか？
  2. MDE：どの程度のリフトなら意味があるか？
  3. サンプルサイズと期間：結果を判断するまでに、どれだけのデータを収集するか？
  4. ガードレール指標：何が悪化してはいけないか（ユーザー当たり売上、ページ読み込み時間、サポートチケット数）？

事前に書き出すことで、偽陽性をひそかに増やす2つの習慣を防げます。ピーキング（有意に見えた瞬間にテストを止めること）と、指標探し（多数の指標のうち、たまたま動いたものを報告すること）です。

CUPED：同じサンプルからより高い精度を得る

必要なサンプル数を確保できないとき、ユーザー、店舗、市場をいつでも追加できるわけではありません。CUPED（Controlled-experiment Using Pre-Experiment Dataの略）は、実験前の情報を利用し、同じデータからより高い精度を得られる場合があります。Microsoftの実験チームは、データを追加収集せずにオンライン実験の感度を高めるため、2013年にこの手法を導入しました(Deng ほか 2013年)。その後、大規模実験における標準的な分散削減手法になりました。

考え方は単純です。実験前から支出の多い顧客であれば、処置の有無にかかわらず、実験中も支出を続ける可能性が高いでしょう。CUPEDはアウトカムのうち予測可能な部分を差し引き、テスト中に実際に変わった部分へ比較の焦点を当てます。

図では、顧客Aはキャンペーン前に$100、キャンペーン中に$110を支出しました。その履歴から約$102を予想できるため、期待値を上回るリフトは$110全額ではなく、わずか$8です。各顧客の予測可能な支出を取り除くと、平均処置効果を変えずにアウトカムのばらつきが小さくなり、効果を検出しやすくなります。

同じ考え方は、店舗単位や市場単位の実験にも役立ちます。小売企業が店頭プロモーションをテストしたいとします。数百店舗を処置群と対照群へ無作為に割り当てるのは、運用上現実的でない場合があります。また、店舗はそれぞれ異なります。規模が大きい店舗、顧客基盤が異なる店舗、地域イベントの影響を受ける店舗があります。CUPEDは各店舗の実験前売上を使い、予測可能な店舗間変動の一部を取り除けます。店舗数を増やすことも、弱い設計を修正することもできませんが、事前期間の売上がテスト中の売上を強く予測する場合、少数店舗のテストをより精密にできます。

形式的には、\(Y\) をアウトカム、\(X\) を実験前の共変量（例：過去30日間の購入）とします。調整後のアウトカムは次のとおりです。

\[Y_{\text{CUPED}} = Y - \theta \cdot (X - \bar{X})\]

ここで、\(\theta = \text{Cov}(Y, X) / \text{Var}(X)\) です。調整後のアウトカムの分散は \(\text{Var}(Y_{\text{CUPED}}) = \text{Var}(Y)(1 - \rho^2)\) まで減少します。\(\rho\) は \(X\) と \(Y\) のピアソン相関です。\(\rho = 0.7\) なら、CUPEDは分散のおよそ半分を取り除き、サンプルを2倍にした場合と同程度の精度を得られます。その後Netflixは、大規模オンライン実験で同程度の分散削減を報告するケーススタディを公開しました(Xie と Aurisset 2016年)。最も一般的な共変量は、実験前期間に測定した同じ指標であり、通常これが最も強い相関を示します。

コードでは、調整は数行だけです。事前期間の支出と実験中の支出の相関が約0.75となるシミュレーション上のキャンペーンでは、リフトの標準誤差を約3分の1削減します。

import numpy as np

# df: one row per customer — pre_spend (prior 30 days), campaign_spend, treatment (0/1)
theta = np.cov(df["campaign_spend"], df["pre_spend"])[0, 1] / df["pre_spend"].var()
df["cuped_spend"] = df["campaign_spend"] - theta * (
    df["pre_spend"] - df["pre_spend"].mean()
)

for metric in ["campaign_spend", "cuped_spend"]:
    t = df.loc[df["treatment"] == 1, metric]
    c = df.loc[df["treatment"] == 0, metric]
    se = np.sqrt(t.var() / len(t) + c.var() / len(c))
    print(f"{metric:15s} lift={t.mean() - c.mean():.2f}  SE={se:.3f}")
# campaign_spend  lift=0.97  SE=0.549
# cuped_spend     lift=1.07  SE=0.364   (33.7% smaller SE — like a much bigger sample)

点推定値はわずかに変化します（0.97 → 1.07）。CUPEDは、群間の事前期間に偶然生じた不均衡による生の差を取り除くため、同じ真の効果を対象としたまま区間が狭くなります。付属Notebookでは df を最初から最後までシミュレーションし、p値（ここでは0.08から0.003へ低下）も報告します。相関を変えて、精度の向上が小さくなったり大きくなったりする様子を確認できます。

テストで結論が出ない場合

決済ページのテストへ戻りましょう。正しい問いは「p値が0.05未満だったか？」ではありません。「重要と考える効果を除外できるほど、テストは精密だったか？」です。

信頼区間を見ます。観測されたリフトは+0.24ポイントですが、95%区間は−0.36から+0.84ポイントであり、小さな損失と大きな改善の両方を含むほど広い区間です。このテストでは結論が出ません。再設計に効果があるとは示していませんが、効果がないとも決して示していません。区間が狭く、導入する価値のあるリフトをすべて除外している場合に限り、その処置を見送ることが妥当になります。

言い換えると、有意でない結果は、自動的に処置の失敗を意味しません。テストが小さすぎた、ノイズが多すぎた、または異常な時期に実施されたというだけかもしれません。

要点

  • 検出する価値がある効果に合わせて設計する。開始前に主要指標、MDE、サンプルサイズ、ガードレールを固定する。サンプルサイズは \(1/\text{MDE}^2\) に比例するため、半分のリフトには4倍のユーザーが必要になる。
  • 有意でない結果は、効果がない証拠ではない。信頼区間で判断する。導入する価値があるリフトがまだ区間内にあるなら、テストはまだ答えを出していない。
  • トラフィックを追加購入できない場合は、代わりにCUPEDで精度を得る。実験前共変量を使い、比較から分散を取り除く。

Xie, Huizhi, と Juliette Aurisset. 2016年. 「Improving the Sensitivity of Online Controlled Experiments: Case Studies at Netflix」. Proceedings of the 22nd ACM SIGKDD International Conference on Knowledge Discovery and Data Mining (KDD ’16), 645–54. https://doi.org/10.1145/2939672.2939733.
