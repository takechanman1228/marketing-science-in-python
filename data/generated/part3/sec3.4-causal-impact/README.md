# Chapter 3.4 committed seeds — provenance

Three files, two sources. Both are committed so the chapter notebook runs with
no downloads, and both are RNG/logic canaries: regenerating them must leave the
working tree clean.

## `weekly_sales.csv` and `ground_truth.csv` — author-generated

The chapter's primary dataset: a national CPG brand that runs an eight-week TV
and PR burst, with two control series the campaign could not reach.

- **Grain**: one row per Monday, 236 weeks (2021-09-06 to 2026-03-09).
- **Observed** (`weekly_sales.csv`): `brand_sales` (the treated series),
  `category_index` and `sibling_line` (the controls), and `campaign`, a flag on
  the eight flight weeks beginning 2025-09-01.
- **Truth** (`ground_truth.csv`): `brand_counterfactual` is the untreated path
  the campaign replaced, so `brand_sales = brand_counterfactual + true_effect`
  up to the cent each column is rounded to. `effect_pct` is the effect as a
  share of the baseline: it ramps to +12%, decays over the four weeks after the
  flight, and is then partly paid back over the following ten. The generator's
  `CARRYOVER_EFFECT` and `PAYBACK_EFFECT` are the source of truth for those
  lengths.
- **Discipline**: the truth grades estimates and builds the failure scenarios.
  It never reaches a model fit.
- No third-party rights attach; released under CC BY 4.0 with the rest of this
  repository's data.

Regenerate by running the generator directly:

```
PYTHONPATH=src python notebooks/part3-causal-inference/causal_impact_data_generation.py
```

`generate_dataset(seed=42)` must reproduce both files byte for byte. The
`PYTHONPATH` matters: `msbook` resolves paths from its own location, so without
it a second clone or worktree writes into whichever checkout `pip install -e .`
last pointed at. Rebuilding the Dunnhumby seed below is a separate step.

## `dunnhumby_store_daily.parquet` — derived from raw

The chapter's closing reality check, where real control stores turn out to
carry no information. Generated by
`notebooks/part3-causal-inference/sec3.4_data_prep.py` from the Dunnhumby
*Complete Journey* transactions (`data/raw/Dunnhumby_kaggle/`,
license-restricted, not in git; see `data/raw/README.md` for how to obtain it).

- **Grain**: one row per (`unique_id`, `ds`); daily unit sales (`y`) and revenue.
- **Series**: 5 stores (`store_292/356/367/381/406`, the five busiest grocery
  stores) plus `chain_total`, which is the **sum of these 5 selected stores**,
  not the whole chain.
- **Filters**: grocery transactions only; fuel and coupon-kiosk items excluded
  (abnormal unit counts would swamp grocery volume).
- **Dates**: `WEEK_NO 1 -> Monday 2012-01-02` anchor; 709 days per series.
- **Aggregation only**: no household-level fields are carried into the seed.

Regenerate by running `sec3.4_data_prep.py` with the repository's `src/` on
`PYTHONPATH`; paths are repo-root anchored via `msbook.paths`.
